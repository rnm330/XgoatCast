# 本地修复与共享兼容方案（2026-09-09）

本次仅修改本地源码，没有部署或上传服务器。音频拦截器、音频采集配置和音频错误映射未改动。此前审计的管理接口鉴权、发布/观看凭证分离不在本次修改范围内。

## 已完成的修复

- 小黑盒 HTTP 与 WebSocket 同样使用 json-bigint 无损解析：超出安全整数范围的数字保存为字符串，正常数量、分页参数仍保留数字类型。
- 小黑盒观看/结束卡片使用 SQLite 持久化任务，每 5 秒检查并退避重试。API 暂未配置时保留任务；每个进程只有一个发送 worker，重复开始事件不会再次发送已保存消息 ID 的卡片。
- 新建观看卡片使用固定 heychat_ack_id，首次尝试后 45 秒内重试；真正发送前（包括排队限流后）重新检查截止时间。平台文档只描述短期去重，不应据此承诺跨重启、无限期“恰好一次”。窗口过期的未知发送结果停止自动重发，保留 uncertain 状态；明确的不可重试错误保留 failed 状态。后台小黑盒配置区显示待补发和待核查数量。结束卡片始终更新原 msg_id，不补发新的结束卡片。
- 共享在观看卡片发送途中结束，会继续把返回的消息更新为结束卡片。任务恢复发现会话已不存在、平台空间不可用时停止发送。
- 共享启动时才读取 Agora SDK，CDN 加载失败时显示错误而非直接导致共享页模块崩溃。
- 屏幕选择在请求发布凭证之前调用，避免网络等待消耗浏览器短期用户激活。
- 防止重复点击并发创建采集和 RTC 连接；停止或失败时同时 stop/close 轨道并离开频道，使后续重试能释放资源。
- 清理旧共享 Cookie 时仅清理对应会话；只有明确 401/404 或 ended 才认定旧会话失效，网络错误不直接解除已有共享限制；跨标签页定期刷新按钮状态。
- 启动 API 的具体错误传回页面，避免网络/服务器错误全部显示为“其他人正在共享”。
- 小黑盒普通文本事件支持后台配置的自定义共享触发词。

补偿范围为观看卡片、结束卡片。最初的“开始共享”入口和管理绑定入口保持原有行为。未收到 msg_id 且去重窗口已过的情况仍需要人工核查，不能无条件自动重发。

## 音频问题的结论与建议（未实现）

现有代码把所有 NOT_SUPPORTED、以及包含 audio 的错误映射为“勾选分享音频”。NOT_SUPPORTED 也可能来自屏幕采集能力、编码器或浏览器兼容性，因此该提示不能用于判定用户没有勾选声音。

现有 SDK 类型文档说明：第二参数为 ScreenAudioTrackInitConfig 对象时，与 auto 一样允许仅返回视频轨道。当前页面也能发布单个视频轨道。本地模拟测试验证了无音频轨道可成功共享；不能把“没勾声音”当成所有失败的根因。生产页加载的是不固定版本的 CDN 脚本，实际版本与本地 npm SDK 不一定一致，真实 Windows 浏览器仍需复测。

建议分三层处理，保留窗口音频优先策略：

1. 首选保留 getDisplayMedia 拦截器，注入 windowAudio: 'window'，沿用现有可选音频配置。以实际返回的音频轨道为准，不以是否识别配置字段判断成功。Chrome 141 加入该 preference hint，但它是提示，不是对操作系统、浏览器及选中窗口都生效的保证。
2. 已取得有效视频、没有音频时直接成功共享，显示非阻断状态“仅共享画面”；不重新弹窗，也不要求勾声音。保留“重新选择并共享声音”的主动操作。
3. 若确认是音频/附加约束兼容错误而未取得视频，提供“兼容模式（仅画面）”按钮，由用户再次点击后用无音频采集兜底。必要时去掉 restrictOwnAudio 等附加约束。权限拒绝、用户取消、非 HTTPS、RTC 网络失败分别处理，不能自动循环弹窗。不要为了兜底静默扩大为整个系统声音；需要声音时可提示改选支持音频的浏览器标签页或升级浏览器。

建议同时记录“采集/获取凭证/加入频道/发布”阶段、原始错误码、实际 SDK 版本、浏览器版本、displaySurface、有无音频轨道，避免把不同故障都归为声音问题；不记录屏幕内容和凭证。

## 其他用户无法共享的条件清单

| 条件 | 证据/处理 |
| --- | --- |
| SDK CDN 未加载 | 已用本地模拟复现模块崩溃，已改为可见错误；网络恢复后刷新页面 |
| 不勾音频、返回单个视频轨道 | 模拟测试可成功；音频降级仅给方案 |
| 重复点击并发启动 | 已复现并修复，启动中禁用按钮且内部防重入 |
| join/publish 失败后采集资源未释放 | 已复现并修复，失败后可重新发起 |
| 获取凭证前长时间等待网络，消耗用户激活 | 已调整调用顺序并验证顺序；实际旧浏览器待联调 |
| 网络错误被显示为链接占用 | 已保留启动请求的具体错误 |
| 旧 Cookie 或其他标签页结束共享后按钮仍锁定 | 已调整定向清理和跨标签页刷新 |
| 小黑盒自定义指令普通文本被过滤 | 已增加实际路由测试并修复 |
| 链接过期、未开始超时、无人观看超时 | 当前业务规则，未放宽；重新发起会话 |
| 同一平台同一用户已有未结束会话 | 当前业务限制；不同用户不互锁、不同平台同 ID 隔离已测试 |
| 链接已锁定给另一浏览器 clientId、清 Cookie 后换了身份 | 当前限制未改，建议重新发起；凭证权限设计按要求未改 |
| 非 HTTPS、浏览器不支持 getDisplayMedia、手机/内置浏览器、系统屏幕权限拒绝 | 静态检查发现的兼容条件，非本次真实设备测试结果；需桌面支持浏览器及系统授权 |
| Agora 凭证缺失/不匹配、过期/额度问题、网络阻断 RTC | 需要相应环境验证；本地仅模拟了凭证失败与 join 失败 |
| 未开放画质、设备无法承担高分辨率/帧率或编码器不可用 | 配置/硬件条件；可降低画质核对。现有 NOT_SUPPORTED 误报声音的映射留待音频方案一起处理 |

## 后台统计核对与图表调整

- 空间实时状态、共享次数、共享时长等统一查询已包含小黑盒。
- 覆盖成员数仅由 KOOK 的成员采集任务写入；小黑盒没有成员采集任务。因此不能称为全平台覆盖人数。本次明确改为“KOOK 覆盖成员数”，展示未纳入的小黑盒活跃房间数量，不把未知人数当作零。
- 小黑盒新增的加入/退出统计事件改用内部 spaceId，避免与 KOOK 同外部 ID 混淆。没有改写历史事件数据。
- 使用趋势：24 小时范围按小时，其他范围按日；缺少使用记录的时间桶补零。
- 覆盖趋势：每个时间桶取最后一份实际快照，不把没有采集的数据补零；移除原来升序 LIMIT 2000 导致最新数据丢失的问题。
- 两图都按真实时间定位横坐标，增加纵轴数值、单位、北京时间、数据点、悬停/点击读数和可展开数据表。覆盖为成员数累加，跨服务器没有人员去重。

## 验证范围

运行服务端测试及前后端构建；数据库测试使用临时目录，未连接生产机器人。共享测试以模拟 SDK/浏览器对象运行实际 hook，覆盖无 SDK、纯视频、失败清理、并发启动、调用顺序和凭证错误；不等同于真实 Windows 浏览器音频联调。卡片测试覆盖大整数、固定去重 ID、重启后恢复更新、去重窗口过期、限流排队后截止检查及发送/结束竞态。
